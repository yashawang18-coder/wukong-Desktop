# 主人请求、姿态桥接与走路帧检查

2026-10-09，本地未提交修改。主人确认部分衔接及缩放正常；多显示器聊天位置尚未人工验收。

## 悟空可以说不

右键和对话的口令、吃饭、喝水、兜风、走走及睡觉邀请共同经过意愿判断。
普通情况下愿意陪伴，但低精力、高压力、并不困或需求已满足时可延后/拒绝。
动作缺失、来源不允许或姿态不兼容仍是技术性 Deferred，不能伪装成宠物拒绝。

短时间催促按请求而非成功完成次数计算。右键与对话共享有上限的会话输入队列，
不因改发另一条口令就清零；动作忙碌期间的请求也计数。默认窗口 60 秒，基础容忍度
5 次，由独立度、淘气、叛逆度及有界提示词倾向修正，最低 3 次；接近上限先延后，
达到上限拒绝。旧请求到期后恢复，不永久改变性格。Stop 和强制魔法不参与意愿拒绝，
但素材和安全中断门禁继续生效。普通自主 Tick 不消费主人请求容忍度。

叛逆度位于档案的“生活节奏与打扰频率”，保存到已有 autonomy-policy.json 的
Commands.Rebelliousness。其他配置为 RequestBurstSeconds、RequestBurstLimit。
提示词只识别少量明确短语（有点叛逆、有自己的主意、不是言听计从）作有限修正；
未知自由文本仍只影响对话，不承诺任意提示词都能转换为数值人格，也不会调用 LLM
解析提示词来授予动作权限。修改、保存提示词后更新；应用启动时同样加载。

面板查看/执行是验收入口，免于意愿拒绝，不计请求压力、动作统计、记忆或性格学习。
实际身体姿态、Busy 和生命周期仍必须准确更新。右键拒绝会出现短气泡，对话返回同一
真实拒绝原因，不回答“好呀”却不执行。

## 执行卡片

卡片动态显示“可立即执行 / 需要调整姿态 / 暂不可执行”及原因。提示只读，不提交动作。
基础动作、走路及吃喝的姿态准备共享既有已批准过渡图，真正执行时重新检查。
空间不足、动作忙碌、待批准和缺桥接分别提示，不统一灰掉后让主人猜原因。
口令的手/吃仍按当前坐趴状态选择分支，不为了展示指定卡片硬切身体。

## 第三帧毛色

截图对应 `assets/action-batches/WK-AUTONOMOUS-PATROL-WALK-v8/frames/cycle-003.png`。
左右共用它，通过 WPF 镜像显示，因此一张源帧异常会同时出现在两方向。
当前图中肩部、背部和后腿有偏红色块，纹理与 cycle-001 等参考帧不一致。

第一次以旧 cycle-003 为目标做局部毛色修正的结果已废弃，未进入资产或运行路径。
第二次改为同时引用已批准的 cycle-002 与 cycle-004，生成一张完整悟空的时间中间态，
不做局部换头或身体拼接。生成母版按 v8 全组相同的 1254→1024 整画布参数处理；
不裁切、不自动居中、不逐帧缩放、不调色，只清除 alpha<=1 及与主体分离的低 Alpha
生成杂点。规范化结果的 Alpha 包围盒为 `[37,219,1011,905]`，与前后帧的地面锚点
连续。

该结果保存为独立候审批次 `WK-AUTONOMOUS-PATROL-WALK-v10`。v8 保持字节不变并继续
作为正式运行素材；v10 除 `cycle-003.png` 外其余 12 张 PNG 与 v8 哈希一致。只有带
`Wukong.PatrolWalkV10Review.enabled` 标记的独立候审 EXE 会使用 v10，且仅允许
DeveloperPreview，不进入自主行为、对话、正式状态、统计或记忆。

仍需主人在 Windows 动画中检查 2→3→4 的脚掌落地、重心、毛色、主体位置、左右镜像
和真实窗口位移。通过前保持 `runtime_approved=false`、`runtime_use=false`。
