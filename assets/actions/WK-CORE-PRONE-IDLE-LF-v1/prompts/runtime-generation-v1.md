# WK-CORE-PRONE-IDLE-LF v1 运行帧生成记录

## 最终采用方式

运行帧没有逐张重新生成角色，而是以五张主人批准的关键帧为唯一输入，在四个相邻区间中分别取 `t=0`、`t=1/3`、`t=2/3`，使用预乘 Alpha 插值构成 12 帧闭环。

```text
K1, K1→K2 1/3, K1→K2 2/3,
K2, K2→K3 1/3, K2→K3 2/3,
K3, K3→K4 1/3, K3→K4 2/3,
K4, K4→K5 1/3, K4→K5 2/3
```

`K5` 与 `K1` 解码像素完全相同，因此不作为第 13 张运行帧重复播放。

## 图像生成候选处理

曾使用批准身份板和 `K1` 尝试生成一个“趴下前一刻”的进入过渡候选。候选没有形成清晰的站立/下压姿态，且存在轻微身份与毛色漂移，因此自检未通过，未进入动作包、清单或预览。

## 不变约束

- 批准关键帧原文件分别保留为运行帧 001、004、007、010，SHA-256 不变。
- 不重新生成脸型、身体、卷尾、毛色和光照。
- 使用 1024×1024 RGBA / sRGB；地面基线 y=861 px。
- 运行节奏为 8 FPS、12 帧、1500 ms 循环。
- 在主人预览审核和真实桌宠渲染器验证前，状态保持 `runtime-candidate`、`runtime_use=false`。
